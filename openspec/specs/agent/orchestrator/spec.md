# agent/orchestrator Specification

## Purpose

Каркас оркестратора агента: цикл tool-calling поверх LLM-клиента (модель → вызовы тулов → результат → повтор), удержание контекста диалога между репликами, загрузка системного промпта роли из файла-скила, контракт делегирования субагентам. Не зависит от конкретных тулов и ролей субагентов.

## Requirements

### Requirement: Цикл tool-calling

Система SHALL выполнять итеративный цикл: отправить запрос к LLM с доступными тулами, исполнить возвращённые вызовы тулов и передать их результаты обратно в LLM, и SHALL завершать цикл, когда модель отвечает без вызовов тулов. При подключённом наблюдателе прогресса система SHALL испускать событие по каждому исполненному тулу.

#### Scenario: Финальный текстовый ответ

- **WHEN** модель отвечает текстом без `tool_calls`
- **THEN** цикл завершается и возвращает текст ответа

#### Scenario: Вызов тулa и финал

- **WHEN** на первой итерации модель вызывает тул, а на второй отвечает текстом
- **THEN** цикл исполняет тул, передаёт результат модели и завершается финальным ответом

#### Scenario: Несколько вызовов подряд

- **WHEN** модель возвращает несколько вызовов тулов в одном ответе
- **THEN** система исполняет их все и передаёт все результаты в следующую итерацию

#### Scenario: Событие прогресса по вызову тулa

- **WHEN** к циклу подключён наблюдатель прогресса и модель вызывает тул
- **THEN** система испускает событие с именем тулa, его аргументами и результатом (или ошибкой), не меняя возвращаемый результат цикла

#### Scenario: Без наблюдателя поведение не меняется

- **WHEN** к циклу не подключён наблюдатель прогресса
- **THEN** цикл выполняется идентично: не испускает событий и возвращает тот же результат

### Requirement: Агрегация токенов прогона

Система SHALL агрегировать использование токенов LLM по всем итерациям цикла в пределах одного прогона и SHALL возвращать агрегированное использование в результате цикла.

#### Scenario: Токены агрегируются по итерациям прогона

- **WHEN** прогон цикла содержит несколько итераций, каждая из которых вернула использование токенов
- **THEN** результат цикла содержит сумму токенов промпта, генерации и общих по всем итерациям прогона, а не только последней итерации

### Requirement: Исполнение вызова тулa из реестра

Система SHALL исполнять вызов тулa по его имени через реестр тулов агента, передавая распарсенные аргументы, и SHALL относить результат к вызову по идентификатору вызова для ответа модели.

#### Scenario: Тул найден и выполнен

- **WHEN** модель вызывает известный тул с валидными аргументами
- **THEN** система исполняет handler тулa и возвращает его результат как сообщение `role:"tool"` с тем же идентификатором вызова

#### Scenario: Неизвестный тул

- **WHEN** модель вызывает тул, которого нет в реестре
- **THEN** система не прерывает цикл, а возвращает сообщение `role:"tool"` с описанием ошибки «тул не найден»

### Requirement: Подача ошибок тулов обратно модели

Система SHALL NOT прерывать цикл при ошибке исполнения тулa (исключение, невалидные аргументы) и SHALL передать описание ошибки модели как результат вызова, чтобы модель могла отреагировать.

#### Scenario: Тул выбросил исключение

- **WHEN** handler тулa выбрасывает ошибку
- **THEN** цикл продолжается, а модели возвращается сообщение `role:"tool"` с текстом ошибки

#### Scenario: Невалидные аргументы вызова

- **WHEN** аргументы вызова функции не являются валидным JSON
- **THEN** система передаёт модели ошибку парсинга аргументов, не прерывая цикл

### Requirement: Ограничение размера результата тулa

Система SHALL усекать сериализованный результат тулa, превышающий заданный лимит символов, и SHALL отметить усечение в сообщении, чтобы большие результаты не переполняли контекст диалога.

#### Scenario: Результат в пределах лимита

- **WHEN** результат тулa короче лимита символов
- **THEN** он передаётся модели целиком без изменений

#### Scenario: Результат превышает лимит

- **WHEN** результат тулa длиннее лимита
- **THEN** система усекает его до лимита и добавляет маркер усечения

### Requirement: Защита от зацикливания

Система SHALL ограничивать число итераций цикла tool-calling верхним пределом и SHALL завершать цикл контролируемо при его достижении, возвращая последний ответ модели и признак усечения по лимиту итераций.

#### Scenario: Достижение лимита итераций

- **WHEN** модель продолжает вызывать тулы до достижения лимита итераций
- **THEN** цикл останавливается и возвращает последний полученный ответ с признаком достижения лимита

#### Scenario: Цикл укладывается в лимит

- **WHEN** модель завершает ответ до достижения лимита итераций
- **THEN** признак достижения лимита отсутствует

### Requirement: Контекст диалога

Система SHALL сохранять историю сообщений диалога между репликами пользователя и SHALL передавать её в каждый запрос к LLM, включая системный промпт, прошлые реплики пользователя/ассистента и результаты тулов.

#### Scenario: Вторая реплика помнит первую

- **WHEN** пользователь посылает второй запрос после завершённого диалога
- **THEN** история первой реплики (включая вызовы тулов и ответы) входит в контекст второго запроса

#### Scenario: Системный промпт присутствует

- **WHEN** оркестратор формирует запрос к LLM
- **THEN** первым сообщением идёт системный промпт роли

### Requirement: Загрузка системного промпта из файла-скила

Система SHALL загружать системный промпт роли из соответствующего файла в каталоге `skills/` по имени роли и SHALL использовать его как системное сообщение в цикле tool-calling.

#### Scenario: Промпт грузится из файла

- **WHEN** оркестратор инициализируется для роли `orchestrator`
- **THEN** системный промпт читается из `skills/orchestrator.md` и используется в запросе

#### Scenario: Файл скила отсутствует

- **WHEN** файл скила для роли не найден
- **THEN** система возвращает ошибку с указанием ожидаемого пути

### Requirement: Делегирование субагентам

Система SHALL предоставлять контракт субагента (имя, описание, исполнение запроса) и реестр субагентов, и SHALL предоставлять тул делегирования, через который LLM может передать подзадачу зарегистрированному субагенту по имени.

#### Scenario: Делегирование зарегистрированному субагенту

- **WHEN** модель вызывает тул делегирования с именем зарегистрированного субагента и инструкцией
- **THEN** система исполняет субагента с инструкцией и возвращает его ответ как результат тулa

#### Scenario: Делегирование неизвестному субагенту

- **WHEN** модель вызывает тул делегирования с именем незарегистрированного субагента
- **THEN** система возвращает результат с ошибкой «субагент не найден», не прерывая цикл

#### Scenario: Нет зарегистрированных субагентов

- **WHEN** реестр субагентов пуст
- **THEN** тул делегирования отсутствует в наборе тулов, переданных модели

### Requirement: Набор тулов оркестратора

Система SHALL формировать набор тулов, передаваемых модели, из тулов реестра агента, и SHALL дополнять его тулом делегирования при наличии зарегистрированных субагентов.

#### Scenario: Тулы реестра доступны модели

- **WHEN** оркестратор запускает цикл с непустым реестром тулов
- **THEN** модели передаются все тулы реестра в формате function-calling

#### Scenario: Тулы реестра как есть

- **WHEN** оркестратор формирует набор тулов
- **THEN** определения тулов реестра передаются без изменения их схем параметров
