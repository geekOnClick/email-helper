# transport/mcp Specification

## Purpose

MCP-сервер над реестром тулов агента: экспонирует доменные тулы по стандарту Model Context Protocol, чтобы внешние MCP-клиенты могли их обнаруживать и вызывать, и исполняет вызовы через существующие обработчики тулов.

## Requirements

### Requirement: Регистрация тулов агента как MCP-тулов

Система SHALL при старте регистрировать все тулы из реестра агента как MCP-тулы: имя тулa, его описание и JSON-схема параметров берутся из определения тулa без изменения. Система SHALL отбрасывать тул `delegate` (внутренний для оркестратора) и не экспонировать его внешним клиентам.

#### Scenario: Все доменные тулы доступны клиенту

- **WHEN** MCP-клиент запрашивает список тулов (`tools/list`) у запущенного сервера
- **THEN** сервер возвращает все тулы реестра агента с их именами, описаниями и JSON-схемами параметров

#### Scenario: Внутренний тул delegate не экспонируется

- **WHEN** сервер регистрирует тулы для MCP
- **THEN** тул `delegate` (внутренний контракт оркестратора) отсутствует в списке MCP-тулов

#### Scenario: Параметры тулa передаются как JSON-схема

- **WHEN** клиент получает определение MCP-тула для `mail.search`
- **THEN** определение содержит JSON-схему параметров, идентичную `inputSchema` доменного тулa

### Requirement: Исполнение вызова тулa через обработчик

Система SHALL исполнять вызов MCP-тула (`tools/call`) через обработчик соответствующего доменного тулa, передавая распарсенные аргументы, и SHALL возвращать результат как текстовый блок в `content`. Система SHALL NOT прерывать сессию при ошибке исполнения тулa и SHALL вернуть ошибку как результат с признаком `isError: true` и текстовым описанием ошибки, не раскрывая секреты (пароли, токены, API-ключи).

#### Scenario: Успешный вызов возвращает результат

- **WHEN** клиент вызывает MCP-тул с валидными аргументами и обработчик тулa завершается успешно
- **THEN** сервер возвращает `content` с текстовым представлением результата и `isError` отсутствует или `false`

#### Scenario: Ошибка исполнения возвращается как isError

- **WHEN** обработчик тулa выбрасывает исключение во время вызова
- **THEN** сервер возвращает результат с `isError: true` и текстом ошибки, не прерывая MCP-сессию

#### Scenario: Секреты не попадают в ответ

- **WHEN** тул возвращает или выбрасывает данные, содержащие учётные данные
- **THEN** сервер не включает сырые секреты (пароли, токены, API-ключи) в `content` ответа

### Requirement: Запуск по stdio-транспорту

Система SHALL предоставлять запуск MCP-сервера по stdio-транспорту для подключения локальных клиентов через стандартные потоки ввода/вывода. Система SHALL корректно завершать сервер при закрытии stdin (EOF) или сигнале прерывания, освобождая занятые ресурсы агента (почтовые сессии, подключения к векторной БД) перед выходом.

#### Scenario: Локальный клиент подключается по stdio

- **WHEN** MCP-сервер запущен в режиме stdio
- **THEN** клиент может подключиться через стандартные потоки, получить список тулов и вызывать их

#### Scenario: EOF на stdin завершает сервер

- **WHEN** stdin сервера закрывается (EOF) во время работы
- **THEN** сервер корректно завершает работу и освобождает ресурсы агента

### Requirement: Запуск по HTTP-транспорту

Система SHALL предоставлять запуск MCP-сервера по Streamable HTTP-транспорту для подключения удалённых клиентов по сети. Система SHALL по умолчанию слушать только localhost, чтобы избежать нежелательной сетевой экспозиции.

#### Scenario: Клиент подключается по HTTP

- **WHEN** MCP-сервер запущен в режиме HTTP и клиент отправляет запрос к эндпоинту
- **THEN** сервер принимает MCP-запросы и отвечает по протоколу Streamable HTTP

#### Scenario: По умолчанию слушает localhost

- **WHEN** HTTP-сервер запускается без явного указания хоста
- **THEN** он принимает соединения только с localhost, не экспонируя тулы в публичную сеть

### Requirement: Сборка агента при старте сервера

Система SHALL при запуске MCP-сервера собирать агента из конфигурации проекта (аккаунты почты, ключи API, клиенты LLM и векторного хранилища) для регистрации тулов в реестре, и SHALL сообщать понятную ошибку с завершением процесса, если конфигурация невалидна или сборка не удалась.

#### Scenario: Успешная сборка и запуск

- **WHEN** MCP-сервер запускается с валидной конфигурацией и аккаунтами
- **THEN** система собирает агента, регистрирует тулы и начинает принимать MCP-запросы

#### Scenario: Невалидная конфигурация

- **WHEN** конфигурация невалидна (отсутствует ключ API, некорректные аккаунты)
- **THEN** система выводит читаемое сообщение об ошибке и завершает процесс с ненулевым кодом, не начиная принимать запросы

### Requirement: Корректное завершение с освобождением ресурсов

Система SHALL освобождать занятые ресурсы агента (почтовые сессии, подключения к FalkorDB) при завершении MCP-сервера по любому из каналов: EOF/stdin, сигнал прерывания, остановка HTTP-сервера.

#### Scenario: Ресурсы освобождаются при выходе

- **WHEN** сервер завершает работу
- **THEN** все открытые почтовые сессии и подключения к векторной БД закрываются до выхода процесса
