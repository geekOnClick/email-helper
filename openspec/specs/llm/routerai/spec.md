# llm/routerai Specification

## Purpose

OpenAI-совместимый клиент RouterAI как единая точка вызова LLM для всех ролей агента: чат-комплишены с поддержкой function calling (tools), конфигурация моделей по ролям, устойчивость к сетевым сбоям.

## Requirements

### Requirement: Чат-запрос к LLM

Система SHALL отправлять OpenAI-совместимый запрос чат-комплишена (`POST /chat/completions`) с набором сообщений (`system`/`user`/`assistant`/`tool`) и SHALL возвращать текстовый ответ ассистента от указанной модели.

#### Scenario: Успешный текстовый ответ

- **WHEN** отправляется запрос с сообщением пользователя к модели `z-ai/glm-5.3-flash`
- **THEN** система возвращает текст ответа ассистента из `choices[0].message.content`

#### Scenario: Запрос с системным промптом

- **WHEN** сообщение с ролью `system` присутствует в запросе
- **THEN** модель получает его как системную инструкцию, и ответ формируется с учётом неё

#### Scenario: Параметры генерации

- **WHEN** запрос содержит `temperature`, `max_tokens`, `top_p`
- **THEN** система передаёт их в запрос, и они применяются к генерации

### Requirement: Конфигурация моделей по ролям

Система SHALL сопоставлять роли агента (`orchestrator`, `analyzer`, `helper`) с идентификаторами моделей из конфигурации и SHALL использовать модель роли по умолчанию, если роль не указана явно.

#### Scenario: Модель роли помощник

- **WHEN** запрашивается роль `helper`
- **THEN** система использует модель из `MODEL_HELPER`

#### Scenario: Модель роли оркестратор

- **WHEN** запрашивается роль `orchestrator`
- **THEN** система использует модель из `MODEL_ORCHESTRATOR`

#### Scenario: Явная модель приоритетнее роли

- **WHEN** в запросе указан явный идентификатор модели
- **THEN** система использует его, переопределяя модель роли

### Requirement: Function calling (tools)

Система SHALL передавать определения функций в формате OpenAI `tools` и SHALL распознавать в ответе модели вызовы функций (`tool_calls`), возвращая их вызывающей стороне в типобезопасном виде.

#### Scenario: Модель вызывает функцию

- **WHEN** модель возвращает ответ с `tool_calls`
- **THEN** система возвращает структурированный список вызовов: имя функции, идентификатор вызова и аргументы (распарсенный JSON)

#### Scenario: Модель отвечает текстом без вызова

- **WHEN** модель возвращает ответ без `tool_calls`
- **THEN** система возвращает только текстовый ответ, без вызовов

#### Scenario: Принудительный выбор функции

- **WHEN** запрос задаёт `tool_choice` равным имени конкретной функции
- **THEN** система передаёт это указание, и модель стремится вызвать именно эту функцию

#### Scenario: Невалидный JSON аргументов вызова

- **WHEN** аргументы вызова функции (`tool_calls[].function.arguments`) не являются валидным JSON
- **THEN** система возвращает ошибку с указанием имени функции, не роняя запрос

### Requirement: Маппинг доменных тулов в схему функций

Система SHALL преобразовывать определения тулов реестра агента (имя, описание, JSON-схема параметров) в формат OpenAI `tools` (схема `function`) для передачи в запрос.

#### Scenario: Тул становится функцией

- **WHEN** в запрос передаётся тул `mail.search` с JSON-схемой параметров
- **THEN** он сериализуется как `{ type: "function", function: { name: "mail.search", description, parameters: <схема> } }`

#### Scenario: Параметры сохраняются

- **WHEN** тул имеет `required` и `properties` в схеме параметров
- **THEN** они без изменений попадают в `parameters` функции

### Requirement: Повтор при временных сбоях

Система SHALL повторять запрос при сетевых ошибках и HTTP-ответах 429 и 5xx с экспоненциальной задержкой, и SHALL вернуть ошибку, если число попыток исчерпано. Таймаут одного запроса SHALL быть ограничен.

#### Scenario: Повтор на 429

- **WHEN** сервер возвращает 429 (слишком много запросов)
- **THEN** система повторяет запрос с задержкой, не более заданного числа попыток

#### Scenario: Повтор на 5xx

- **WHEN** сервер возвращает 500/502/503
- **THEN** система повторяет запрос с экспоненциальной задержкой

#### Scenario: Исчерпание попыток

- **WHEN** все попытки повторов исчерпаны безуспешно
- **THEN** система возвращает ошибку с указанием статуса и причины, не раскрывая секрет

#### Scenario: Таймаут запроса

- **WHEN** ответ сервера не получен в течение заданного таймаута
- **THEN** система прерывает запрос и либо повторяет, либо возвращает ошибку таймаута

### Requirement: Обработка некорректного ответа

Система SHALL валидировать структуру ответа API и SHALL возвращать понятную ошибку при malformed-ответе (отсутствие `choices`, повреждённый JSON), не выбрасывая необработанное исключение наружу.

#### Scenario: Malformed JSON

- **WHEN** тело ответа не является валидным JSON
- **THEN** система возвращает ошибку парсинга ответа с указанием модели

#### Scenario: Пустой choices

- **WHEN** ответ не содержит `choices` или `choices[0].message`
- **THEN** система возвращает ошибку о неожиданной структуре ответа

### Requirement: Сокрытие API-ключа

Система SHALL NOT включать `ROUTERAI_API_KEY` (или его часть) в сообщения об ошибках, логи и текст возвращаемых ответов.

#### Scenario: Ошибка без раскрытия ключа

- **WHEN** запрос завершается ошибкой аутентификации (401) или сети
- **THEN** сообщение об ошибке не содержит значения API-ключа

#### Scenario: Ключ не в логах

- **WHEN** система логирует детали запроса/ответа
- **THEN** в лог не попадает Bearer-токен или тело Authorization-заголовка
