# Design

## Context

Текущий CLI REPL (`src/transport/cli/repl.ts`) принимает свободный текст и отправляет его оркестратору (`orchestrator.run(text)`). Это непредсказуемо и расходует токены на разбор интента. Пользователь хочет guided-команды (`/find`, `/analyze`, `/download`, `/send`) с детерминированным мастером сбора критериев.

Существующие компоненты для переиспользования:
- **Тулы реестра:** `mail.search` (`{ login, criteria }`), `mail.fetch` (`{ login, uid }`), `mail.downloadAttachments` (`{ login, uid, targetDir }`), `mail.send` (`{ login, to, subject, text, ... }`) — вызываются через `getTool(name).handler(args)`.
- **MailSessionStore:** `getSharedSessionStore()` — для предзаготовленных сессий (опц.); команды вызывают тулы напрямую, тулы сами работают со store.
- **Анализатор:** `createAnalyzer({ client, config, toolLogger })` → `Subagent` с `.run(instruction)`. Создаётся в `composeAgents` как внутренний субагент; для `/analyze` нужен доступ из REPL.
- **SessionStats** (Фаза 8): уже в `BootstrapResult`, `/stats` уже работает.
- **Config:** `Account[]` с `{ provider, login, password, authStrategy }` — источник списка аккаунтов для выбора почты.
- **MockConsoleIO** (`tests/mock-io.ts`): `readline()`, `write()`, `isTTY()` — для тестирования мастера ввода.

## Goals / Non-Goals

**Goals:**
- REPL принимает только slash-команды (свободный текст отклоняется).
- 4 guided-команды с мастером сбора критериев (формат `ключ - значение`).
- Выбор почты при нескольких аккаунтах.
- `/analyze` через субагента-анализатора (LLM).
- `/send` с черновиком и подтверждением.
- Минимальные изменения существующего кода; переиспользование тулов и анализатора.

**Non-Goals:**
- Семантический поиск (`/semantic`) — отложен.
- Веб-интерфейс — Фаза 9.
- Изменение MCP-транспорта (он остаётся stateless, экспонирует тулы как есть).
- Изменение доменных тулов (mail.search/fetch/send) — используются как есть.

## Decisions

### D1: REPL только slash-команды — убрать свободный текст и `orchestrator.run`

**Выбор:** `CliRepl` убирает `runQuery(text)` (отправку свободного текста оркестратору). Все не-slash строки → сообщение «доступен только slash-командный режим» + подсказка. `/reset` убран (история не нужна — нет диалога с агентом; каждая команда stateless). `/help`, `/clear` убраны по решению пользователя.

**Почему:** Пользователь явно хочет предсказуемости. Свободный текст через LLM непредсказуем. Guided-команды детерминированы.

**Альтернатива:** Оставить свободный текст как fallback — отвергнута (противоречит решению пользователя).

### D2: Мастер ввода — отдельный модуль `src/transport/cli/prompts.ts`

**Выбор:** Модуль с функциями:
- `parseCriteriaLine(line): { field, value } | null` — парсинг `ключ - значение`, валидация поля (`тема`/`дата`/`отправитель`).
- `validateValue(field, value): string | null` — валидация значения (ISO-дата для `дата`, email для `отправитель`), возвращает ошибку или null.
- `promptSearchCriteria(io): Promise<SearchCriteria | null>` — цикл сбора: читает строки, парсит, валидирует, при ошибке просит повторить; пустая строка завершает сбор; возвращает критерии или null (отмена).
- `promptSendCriteria(io): Promise<ComposeMailInput | null>` — аналогично для `/send` (тема, текст, получатель).

**Почему:** Переиспользуемая логика парсинга/валидации, тестируемая через MockConsoleIO. Формат `ключ - значение` простой, без библиотек.

**Альтернатива:** Использовать `inquirer`/`prompts` — отвергнута (новая зависимость, избыточность для readline).

### D3: Выбор почты — `promptAccount(io, accounts): Promise<MailAccount | null>`

**Выбор:** Функция в `prompts.ts`: если `accounts.length === 0` → сообщение об отсутствии + return null; если 1 → return accounts[0] без запроса; если ≥2 → показ списка логинов (1. login1, 2. login2) + чтение выбора. Выбор после сбора критериев (как в спеке).

**Почему:** Одиночный аккаунт — частый случай (не беспокоить пользователя). Несколько — явный выбор.

### D4: Обработчики команд — `src/transport/cli/commands/`

**Выбор:** Каталог с модулями по командам:
- `find.ts` — `runFindCommand(deps): Promise<void>`.
- `analyze.ts` — `runAnalyzeCommand(deps): Promise<void>`.
- `download.ts` — `runDownloadCommand(deps): Promise<void>`.
- `send.ts` — `runSendCommand(deps): Promise<void>`.

`deps` включает: `io`, `accounts`, `analyzer` (для /analyze), `downloadDir`. Команды вызывают тулы через `getTool(name).handler(args)` напрямую (не через оркестратор). Вывод — через `io.write(format...)`.

**Почему:** Изоляция логики команд; тестируемость каждой команды отдельно; REPL остаётся тонким маршрутизатором.

**Альтернатива:** Одна функция-обработчик — отвергнута (монолит, сложно тестировать).

### D5: `/analyze` — прямой вызов субагента-анализатора, не через оркестратор

**Выбор:** `bootstrap()` создаёт анализатор через `createAnalyzer({ client, config, toolLogger })` отдельно и возвращает в `BootstrapResult.analyzer` (наряду с `orchestrator`). `/analyze` вызывает `analyzer.run("Проанализируй письмо: <тема, от, дата, тело>")` напрямую, передавая тело письма из `mail.fetch`.

**Почему:** Оркестратор — для диалога/делегирования, которого больше нет (guided-режим). Анализатор независим (`Subagent.run`). Прямой вызов проще, без цикла delegate. `orchestrator` остаётся в `BootstrapResult` для `/stats` (который читает `SessionStats`, не оркестратор) — но фактически оркестратор больше не используется в guided-режиме.

**Альтернатива:** Делегировать через оркестратор (`orchestrator.run("проанализируй")`) — отвергнута (лишний цикл LLM для разбора интента, который уже детерминирован).

### D6: `/download` — системная папка загрузок

**Выбор:** Путь загрузки — `os.homedir() + '/Загрузки'` (русская локаль пользователя) с fallback на `~/Downloads` если `Загрузки` не существует. Проверка/создание папки через `fs.mkdirSync(dir, { recursive: true })` перед вызовом `mail.downloadAttachments`.

**Почему:** Решение пользователя — системная папка загрузок. Русская локаль (пути «Рабочий стол»).

### D7: `/send` — подтверждение да/нет

**Выбор:** После сбора (тема, текст, получатель) + выбора аккаунта — формирование черновика, вывод через `formatDraft(draft)`, затем `promptConfirm(io, 'Отправить? (да/нет)'): Promise<boolean>`. Чтение одной строки, парсинг «да»/«нет»/«yes»/«no» (case-insensitive). При подтверждении — `mail.send` handler; при отказе — сообщение об отмене.

**Почему:** Детерминированное подтверждение без LLM. Простой парсинг.

### D8: Несколько совпадений — показ 5 + UID

**Выбор:** Для `/analyze` и `/download` (нужно конкретное письмо): после `mail.search`, если `messages.length > 1` → `formatMessageList(messages.slice(0, 5))` (тема, отправитель, дата, UID) + `promptUid(io, messages): Promise<number | null>` (читает число, проверяет что UID в списке). Если `messages.length === 1` — используется это письмо. Для `/find` — вывод всех (до 50) без выбора.

**Почему:** Решение пользователя — показать первые 5 + уточнить. UID — уникальный идентификатор письма в папке.

### D9: `BootstrapResult` расширяется — добавляется `analyzer` и `accounts`

**Выбор:** `bootstrap()` возвращает `{ orchestrator, analyzer, accounts, stats, cleanup }`. `accounts` — для выбора почты в командах. `analyzer` — для `/analyze`.

**Почему:** Командам нужны аккаунты и анализатор. `orchestrator` сохраняется (для `/stats` через stats, но фактически не вызывается; оставлен чтобы не ломать MCP, который использует `bootstrap` и берёт `{ cleanup }`).

## Risks / Trade-offs

- **D1 — breaking для существующих тестов REPL:** Тесты `cli-repl.test.ts`, `cli-repl-progress.test.ts`, `cli-repl-integration.test.ts`, `cli-e2e-*.test.ts` проверяют свободный текст/`/help`/`/reset` — потребуют переписывания. Mitigation: новые тесты для guided-команд; старые обновляются или заменяются.
- **D5 — анализатор создаётся отдельно:** Двойная инициализация (orchestrator создаёт анализатор внутри, + bootstrap создаёт ещё один). Риск: два инстанса анализатора. Mitigation: `bootstrap` создаёт один инстанс и передаёт в `composeAgents` (через опцию), либо `composeAgents` возвращает анализатор наружу. Выберу: `composeAgents` принимает опцию `returnSubagents: true` и возвращает `{ orchestrator, analyzer, helper }`, либо bootstrap создаёт анализатор сам и передаёт в composeAgents. Проще — bootstrap создаёт анализатор, передаёт в composeAgents (чтобы delegate работал), и bootstrap возвращает тот же инстанс.
- **D6 — папка `Загрузки` может не существовать:** `mkdirSync` создаёт. Но если локаль не русская — fallback на `Downloads`.
- **D8 — UID ввод вручную:** Пользователь может ввести несуществующий UID. Mitigation: валидация против списка, повторный запрос.
