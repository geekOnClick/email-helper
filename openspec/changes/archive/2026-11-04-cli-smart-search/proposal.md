# Proposal

## Why

Текущие CLI-команды поиска (`/analyze`, `/analyze-many`) требуют от пользователя вручную собирать структурированные критерии (тема/отправитель/диапазон дат) построчным мастером. Это неудобно для запросов естественным языком вроде «найди мне последнее письмо от отправителя ded@ded.ru» или «собери мне последние 10 писем по теме Урок». Нужна команда, где пользователь указывает только промпт, а LLM сама разбирает его в критерии поиска и переиспользует уже доказанную машину пакетного поиска (локальная фильтрация + пагинация).

## What Changes

- Добавлена команда `/smart-search`: пользователь вводит произвольный промпт одной строкой → прямой one-shot вызов `RouterAiClient` (роль `helper`, как в `/smart-send`) парсит промпт в структурированные критерии `{ тема?, отправитель?, дата с?, дата по?, количество }` → переиспользуется `collectAllMessages` (сервер получает ТОЛЬКО диапазон дат; тема/отправитель фильтруются локально) → найденные письма сортируются по дате убыванием и берутся top-N.
- Если промпт запрашивает одно письмо (или не указывает число — по умолчанию N=1), система показывает самое свежее совпадение целиком (отправитель, тема, дата, UID, тело письма) без LLM-анализа.
- Если промпт запрашивает несколько писем (N>1), система выводит таблицу найденных (как `/analyze`/`/find-all`) и спрашивает UID для открытия конкретного письма — открытое письмо показывается целиком (с телом) без LLM-анализа.
- Диапазон дат при отсутствии явной даты в промпте: bounded-окно `MAIL_SEARCH_FALLBACK_DAYS` (по умолчанию 180), как у бывшего `/find` — быстро и достаточно для типичных «последних» писем.
- Потолок числа писем: переиспользуется `ANALYZE_MANY_MAX_EMAILS` (дефолт 10) и как дефолтное N, когда промпт не называет число, и как хард-кап (нельзя запросить больше).
- Добавляется `/smart-search` в список slash-команд (требование «Slash-команды guided-режима»), в маршрут REPL и в справку `formatCommandHelp`.
- **Не меняется**: тулы `mail.*` (`mail.search`, `mail.fetch` и др.), MCP-путь оркестратора, спеки `mail/*`, остальные CLI-команды.

## Capabilities

### New Capabilities

_(нет — новая команда принадлежит существующей capability `transport/cli`.)_

### Modified Capabilities

- `transport/cli`: обновляется требование «Slash-команды guided-режима» (добавляется `/smart-search` в список); добавляются два новых требования — «Мастер /smart-search» (сбор промпта одной строкой) и «Команда /smart-search» (LLM-парсинг промпта →пакетный поиск → вывод/открытие письма без анализа).

## Impact

- **Исходный код CLI-слоя**: новый `commands/smart-search.ts`; обновление `commands/index.ts`, `repl.ts` (маршрут + `GuidedCommandDeps`), `format.ts` (`formatCommandHelp`), `prompts.ts` (мастер ввода промпта `promptSmartSearchPrompt`); переиспользуются `collectAllMessages` (search-aggregator), `promptAccount`, `promptUid`, `formatMessageList`, `RouterAiClient`.
- **Конфигурация**: переиспользуются `ANALYZE_MANY_MAX_EMAILS` (как потолок и дефолт N) и `MAIL_SEARCH_FALLBACK_DAYS` (как bounded-окно); новые env-значения не вводятся.
- **Зависимости**: новые npm-зависимости не требуются (LLM-клиент и `collectAllMessages` уже есть).
- **Тесты**: новые тесты для `/smart-search` (LLM-парсинг промпта, поведение N=1/N>1, усечение по потолку, bounded-окно) + обновлённые маршруты REPL и справка команд.
- **MCP-путь и тулы `mail.*`**: не затрагиваются.
