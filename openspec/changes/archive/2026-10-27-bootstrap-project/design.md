# Design

## Context

Проект пуст (только `PLAN.md`, `.gitignore`, `agent-accounts.txt`). Разработка ведётся на TypeScript/Node.js под Linux, с Docker для FalkorDB. Это первый change — задаёт технические соглашения, которые унаследуют все последующие фазы. Ограничения зафиксированы в `PLAN.md` (раздел 2): ESM, strict, Node ≥ 20, RouterAI как LLM-провайдер, FalkorDB в Docker.

## Goals / Non-Goals

**Goals:**
- Готовый к разработке TS-проект: компилируется, линтер проходит, один smoke-тест зелёный.
- Воспроизводимое локальное окружение: одна команда `docker compose up -d` поднимает FalkorDB.
- Единая схема конфигурации (zod) для всех последующих фаз.
- Документная база: `agent.md` + `skills/*.md` как источник правды по архитектуре (для агентных циклов следующих фаз).

**Non-Goals:**
- Реализация тулов, агентов, LLM-клиента, почтовых провайдеров — это Фазы 1–4.
- Подключение реальных аккаунтов к коду — только схема конфига.
- MCP-сервер, CLI/Telegram — Фазы 5–7.

## Decisions

### D1. ESM (`type: module`) вместо CommonJS
**Почему:** Современный экосистемный стандарт (`falkordb`, `imapflow`, `nodemailer` поддерживают ESM). сокрощает `import/export`. Альтернатива CJS усложнила бы смешивание с ESM-only зависимостями будущих фаз.
**Альтернатива рассмотрена:** CJS —rejected, conflicts с ESM-only deps.

### D2. TypeScript strict + `moduleResolution: bundler`
**Почему:** строгая типизация снижает число бъгов в туловых агентах; `bundler` resolution совместим с ESM и `vitest`.

### D3. Vitest вместо Jest
**Почему:** нативная поддержка ESM/TypeScript из коробки, быстрее, чище конфиг. Идеален для последующих фаз с моками IMAP/LLM.

### D4. zod для схемы конфигурации
**Почему:** runtime-валидация `.env` с читаемыми ошибками; единый источник правды для типов конфига во всём проекте. Альтернатива `envalid` — слабее для сложных вложенных структур (список аккаунтов).

### D5. FalkorDB через docker-compose (server-образ)
**Почему:** Образ `falkordb/falkordb-server:latest` (без браузера) — лёгкий, для production-стиля. Браuseр не нужен в коде. Персистентность через named volume + AOF (`--appendonly yes`). Пароль через `REDIS_ARGS=--requirepass`.
**Альтернатива:** `falkordb/falkordb` (с браузером на :3000) — оставим как опцию в комментарии для дебага.

### D5.1. FalkorDB тестовый vs прод-конфиг
server-образ + пароль из `.env` (`FALKORDB_PASSWORD`). Порт 6379 наружу (для разработки). Для тестов — тот же контейнер, отдельная тестовая база.

### D6. Структура `src/` с заглушками-модулями
Каталоги заранее размечены под архитектуру из `PLAN.md` (агенты/тулы/llm/config/transport/mcp). В каждом — минимальный `index.ts` с экспортом-заглушкой или пустым интерфейсом, чтобы импорты компилировались и следующие фазы дописывали реализацию, не перестраивая структуру.

### D7. `agent.md` и `skills/` как живые документы
`agent.md` описывает назначение и архитектуру (сокращённая выжимка из `PLAN.md`). `skills/*.md` — системные промпты ролей (оркестратор/анализатор/помощник): рамка ответственности, доступные тулы, формат ответа. Полными промптами наполняются в Фазе 2, здесь — каркас.

## Risks / Trade-offs

- **[Риск: FalkorDB требует Redis 8.0.0+]** Образ `falkordb/falkordb-server:latest` уже включает совместимый Redis, так что отдельная установка Redis не нужна. → Mitigation: зафиксировать тег образа (например `:latest` на старте, пин к версии при стабилизации) и healthcheck через `redis-cli ping`.
- **[Риск: версии зависимостей дрейфуют]** Без pin-версий сборка может сломаться. → Mitigation: фиксируем `package.json` через `npm install --save-exact` для ключевых пакетов; `package-lock.json` в git.
- **[Трейд-офф: `falkordb` npm vs `redis`+module]** `falkordb` клиент высокоуровневый, выбран для простоты; ниже контроль над протоколом — приемлемо для старта.

## Migration Plan

Это greenfield-проект, миграции нет. Развёртывание:
1. `npm install`
2. `cp .env.example .env` + заполнить (`agent-accounts.txt` → `.env`).
3. `docker compose -f docker/docker-compose.yml up -d`
4. `npm test` — smoke-тест.
5. `openspec validate` — проходит.

Откат: удалить созданные файлы, `docker compose down -v`.
