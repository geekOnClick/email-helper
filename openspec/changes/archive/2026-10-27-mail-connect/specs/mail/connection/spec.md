# Spec Delta

## Purpose

Подключение к почтовому ящику по IMAP (Яндекс, Outlook) и получение списка папок, с плавающей стратегией аутентификации `basic` | `oauth2` (Microsoft device code flow для Outlook при отказе basic-auth).

## ADDED Requirements

### Requirement: Подключение к ящику по IMAP

Система SHALL устанавливать защищённое IMAP-соединение с сервером провайдера, используя учётные данные аккаунта, и возвращать результат подключения. Яндекс — `imap.yandex.ru:993`; Outlook — `outlook.office365.com:993`.

#### Scenario: Успешное подключение к Яндекс с паролем приложения

- **WHEN** запрашивается подключение к Яндекс-аккаунту с корректным логином и паролем приложения
- **THEN** система устанавливает IMAP-соединение с `imap.yandex.ru:993` (TLS) и возвращает успешный результат

#### Scenario: Успешное подключение к Outlook с выбранной стратегией

- **WHEN** запрашивается подключение к Outlook-аккаунту с корректными учётными данными и работающей стратегией аутентификации
- **THEN** система устанавливает IMAP-соединение с `outlook.office365.com:993` (TLS) и возвращает успешный результат

#### Scenario: Неверные учётные данные

- **WHEN** учётные данные аккаунта отклонены сервером
- **THEN** система возвращает ошибку аутентификации с понятным сообщением, не раскрывая секрет

#### Scenario: Сервер недоступен

- **WHEN** IMAP-сервер недоступен по сети или превышен таймаут подключения
- **THEN** система возвращает ошибку подключения с указанием провайдера и причины

### Requirement: Стратегии аутентификации

Система SHALL поддерживать стратегии аутентификации `basic` (логин + пароль) и `oauth2` (OAuth2 access token по SASL XOAUTH2), выбираемые per-аккаунт через конфигурацию. Архитектура SHALL допускать добавление новой стратегии без изменения логики подключения.

#### Scenario: Стратегия basic

- **WHEN** у аккаунта `authStrategy` равно `basic`
- **THEN** система авторизуется логином и паролем из конфигурации аккаунта

#### Scenario: Стратегия oauth2

- **WHEN** у аккаунта `authStrategy` равно `oauth2`
- **THEN** система авторизуется access token через механизм XOAUTH2

#### Scenario: Неподдерживаемая стратегия

- **WHEN** у аккаунта `authStrategy` не равен `basic` или `oauth2`
- **THEN** система возвращает ошибку конфигурации и не пытается подключиться

### Requirement: Автоопределение стратегии для Outlook

Для Outlook-аккаунта система SHALL проверять работоспособность basic-auth и при отказе SHALL переходить к OAuth2 device code flow для Microsoft identity platform v2.0.

#### Scenario: Basic-auth работает для Outlook

- **WHEN** проверочный запрос basic-auth к `outlook.office365.com:993` успешен
- **THEN** система использует стратегию `basic` для данного аккаунта

#### Scenario: Basic-auth отклонён для Outlook

- **WHEN** проверочный запрос basic-auth отклонён сервером
- **THEN** система инициирует OAuth2 device code flow и использует стратегию `oauth2`

### Requirement: OAuth2 device code flow для Microsoft

При стратегии `oauth2` для Outlook система SHALL выполнять device code flow против Microsoft identity platform v2.0: запрашивать device code, предъявлять пользователю URL авторизации и user code, обменивать код на access + refresh token.

#### Scenario: Инициация device code flow

- **WHEN** запускается OAuth2 для Outlook-аккаунта без действительного токена
- **THEN** система выводит URL `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/devicecode` и user code, ожидая завершения авторизации пользователем

#### Scenario: Пользователь завершил авторизацию

- **WHEN** пользователь вводит user code и завершает вход в браузере
- **THEN** система получает access token и refresh token и выполняет подключение по IMAP

#### Scenario: Истёкший device code

- **WHEN** пользователь не завершил авторизацию до истечения срока device code
- **THEN** система возвращает ошибку с предложением повторить flow

#### Scenario: Отказ пользователя

- **WHEN** пользователь отменяет авторизацию в браузере
- **THEN** система возвращает ошибку и не подключается

### Requirement: Хранение и обновление OAuth2-токенов

Система SHALL сохранять refresh token (и метаданные срока действия) в локальном хранилище вне git и SHALL использовать его для получения новых access token без повторной интерактивной авторизации.

#### Scenario: Обновление access token

- **WHEN** access token истёк, но refresh token действителен
- **THEN** система получает новый access token через refresh token и повторяет операцию без участия пользователя

#### Scenario: Refresh token отсутствует или отозван

- **WHEN** refresh token отсутствует в хранилище или отклонён Microsoft
- **THEN** система инициирует новый device code flow

### Requirement: Жизненный цикл IMAP-сессии

Система SHALL управлять жизненным циклом IMAP-сессии: открытие при подключении, корректное закрытие с освобождением ресурсов, защита от утечек соединений.

#### Scenario: Подключение открывает сессию

- **WHEN** подключение успешно
- **THEN** система держит активную IMAP-сессию, доступную для последующих операций

#### Scenario: Закрытие освобождает соединение

- **WHEN** запрашивается закрытие подключения
- **THEN** система корректно закрывает IMAP-сессию и освобождает сетевое соединение

#### Scenario: Повторное подключение после закрытия

- **WHEN** сессия была закрыта и запрашивается новое подключение того же аккаунта
- **THEN** система устанавливает новую сессию без ошибок

#### Scenario: Ошибка операции не оставляет висящее соединение

- **WHEN** операция завершается ошибкой
- **THEN** система закрывает сессию или возвращает её в пригодное состояние, не оставляя висящее соединение

### Requirement: Список папок ящика

После успешного подключения система SHALL возвращать список папок ящика: имя, разделитель пути, флаги (включая `\Inbox`, `\Sent`, `\Drafts`).

#### Scenario: Список папок возвращён

- **WHEN** запрашивается список папок при активном подключении
- **THEN** система возвращает непустой список, содержащий папку «Входящие» (`\Inbox`)

#### Scenario: Запрос папок без подключения

- **WHEN** запрашивается список папок без активного подключения
- **THEN** система возвращает ошибку с указанием, что подключение не установлено

### Requirement: Безопасное хранение учётных данных

Система SHALL хранить пароли приложений и OAuth2-токены только в локальных файлах вне git (`.env` для паролей, отдельный token store для OAuth2-токенов). Система SHALL NOT логировать секреты или выводить их в сообщения об ошибках.

#### Scenario: Token store вне git

- **WHEN** создаётся файл хранилища OAuth2-токенов
- **THEN** путь хранилища добавлен в `.gitignore` и не отслеживается git

#### Scenario: Секреты не попадают в логи

- **WHEN** происходит ошибка аутентификации или подключения
- **THEN** сообщение об ошибке не содержит пароля, access token или refresh token
