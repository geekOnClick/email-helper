# Proposal

## Why

Проект предоставляет почтовый помощник (поиск, анализ, отправка писем) через
CLI REPL со slash-командами. CLI хорошо подходит для автоматизации, но
пошаговые guided-диалоги (`readline`-циклы) и потоковый вывод LLM-анализа
неудобны для чтения в терминале: тело письма и развёрнутый анализ LLM
выводятся как сплошной текст, без структуры, и теряются среди прогресса
tool-вызовов.

Веб-интерфейс на React решает это: макет «почтовый клиент» (список писем
слева, чтение и анализ справа) даёт читаемое представление писем и
результатов анализа, а формы вместо пошаговых диалогов ускоряют операции
поиска и отправки. Веб-альтернатива не заменяет CLI — оба транспорта работают
поверх общего ядра (тулы, агенты, LLM-клиенты) и активируются в одном
процессе.

## What Changes

Добавляется новый транспорт **web**: HTTP REST API встроенным Node-сервером
плюс React + Vite SPA с Material-UI. Веб поднимается в том же процессе, что и
CLI (`npm start` запускает REPL, `npm run web` — веб-сервер), переиспользует
bootstrap-сборку агентов/тулов и доменные команды.

- **Бэкенд (Node HTTP):** REST-эндпоинты над существующими тулами
  (`mail.search`, `mail.fetch`, `mail.send`, `mail.connect`,
  `mail.downloadAttachments`) и командами (`/smart-search`, `/analyze`,
  `/analyze-many`, `/analyze-attachments`, `/smart-send`, `/add-account`).
  Команды-функции (`runSmartSearchCommand` и др.) рефакторятся для приёма
  структурированных DTO вместо `ConsoleIO`, чтобы их можно было вызывать и из
  CLI (через адаптер ввода-вывода), и из API (через HTTP-обработчик).
- **Фронтенд (React + Vite + Material-UI):** SPA с макетом почтового клиента —
  тулбар команд сверху, список писем слева, чтение тела/анализ справа.
  Выбор аккаунта через дропдаун при операции. Формы для поиска и отправки;
  LLM-анализ отображается структурированным отчётом в правой панели.
- **Чтение тела письма:** новая операция (ранее в CLI доступна только через
  `/analyze`) — фетч полного письма (`mail.fetch`) с телом и вложениями,
  читаемый рендер справа.
- **Конфигурация:** новые env-переменные (`WEB_PORT`, `WEB_HOST`) и npm-скрипты
  (`web`, `web:dev`, `web:build`).

## Capabilities

### New Capabilities
- `transport/web`: веб-транспорт — Node HTTP REST API, React/Vite SPA,
  макет почтового клиента, выбор аккаунта, читаемый рендер писем и анализа.

### Modified Capabilities
- `transport/cli`: команды (`/smart-search`, `/smart-send`, `/analyze`,
  `/analyze-many`, `/analyze-attachments`, `/add-account`) выделяют
  доменную логику в чистые функции, принимающие DTO вместо `ConsoleIO`;
  CLI становится тонким адаптером ввода-вывода над этими функциями.
- `config/account-management`: валидация и сохранение аккаунта через
  `/add-account` доступны из веба (тот же путь записи в `.env`).

## Impact

- **Код:** новый каталог `src/transport/web/` (бэкенд `server.ts`,
  `api/`-обработчики, фронтенд `client/`); рефакторинг
  `src/transport/cli/commands/*.ts` (выделение DTO + чистой логики);
  расширение `src/index.ts` флагом `--web`.
- **Зависимости:** новые npm-пакеты — `react`, `react-dom`, `vite`,
  `@vitejs/plugin-react`, `@mui/material`, `@emotion/react`, `@emotion/styled`,
  `@mui/icons-material`; dev-зависимости `@types/react`, `@types/react-dom`.
  Бэкенд использует встроенный `node:http` (без Express/Fastify).
- **Конфигурация:** `.env` += `WEB_PORT` (по умолчанию 3000), `WEB_HOST`
  (по умолчанию `127.0.0.1`); `package.json` += скрипты `web`, `web:dev`,
  `web:build`.
- **Тесты:** unit-тесты для API-обработчиков и DTO-функций команд; smoke-тест
  SPA-сборки; существующие CLI-тесты адаптируются под рефакторинг (адаптер
  `ConsoleIO` обёртывает чистую логику — контракт сохраняется).
- **Безопасность:** веб слушает `127.0.0.1` (localhost-only, как MCP HTTP);
  пароли аккаунтов не передаются в API (извлекаются бэкендом из `.env` по
  `login`+`provider`, как в `mail.connect`).
- **Совместимость:** CLI сохраняет текущее поведение; веб — аддитивная
  альтернатива, не затрагивающая MCP-путь тулов.
