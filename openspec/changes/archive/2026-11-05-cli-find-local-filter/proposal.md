# Proposal

## Why

Команда `/find` не находит письма, которые реально есть в ящике, и которые при этом корректно
находятся через MCP-тул `mail.search` (когда вызывающий передаёт `subject` + надёжный `since`).

Воспроизведено на реальном ящике `kozloww1508@yandex.ru` для письма «Успешная оплата» от
`no-reply@igm.gg` от 2026-11-03 (лежит в INBOX, uid=35601):

| Запрос `/find` (через `buildSearchCriteria`)            | Результат |
|----------------------------------------------------------|----------|
| `subject` + `from` (как `/find`, без `since`)            | total=0 — **не найдено** |
| `subject` only                                           | total=3, только СТАРЫЕ (2016/2020/2023), целевое за 2026 пропущено |
| `from` only                                              | total=0 — **не найдено** |
| `subject` + `since` (как MCP)                            | total=26, найдено uid=35601 ✅ |
| `from` + `since` (как MCP)                               | total=0 — не найдено |

Корневая причина: `/find` отправляет на сервер Яндекса `subject` **и** `from` вместе, без
`since`. Серверный IMAP SEARCH Яндекса по кириллическим `subject`-литералам и `from` ненадёжен
(возвращает 0 либо неполный набор). В тулe `mail.search` при пустом серверном результате
срабатывает bounded fallback (`buildNarrowedQuery`), но он ошибочно считает `from` «надёжным»
критерием — поэтому НЕ добавляет дефолтный `SINCE now−180д`, а сужается по `from` → снова 0 →
«Ничего не найдено».

MCP-клиент обходит это: всегда передаёт надёжный `since` и фильтрует тему/отправителя локально.
Команда `/find-all` уже решила ту же проблему подходом «на сервер только даты, тема/отправитель
— локально» (через `collectAllMessages`, change `cli-find-all-command`, design D1).

## What Changes

- `/find` формирует запрос к `mail.search` как `/find-all`: на сервер передаётся **только**
  диапазон дат (`since`/`before`), а `subject`/`from` фильтруются **локально** через
  существующий агрегатор `collectAllMessages` (переиспользование проверенной машины `/find-all`).
- Явная `дата` из мастера → `since` = полночь указанного дня, `before` = следующий день (один
  день включительно), как в `/find-all`.
- Без явной даты → bounded `since` = `now − MAIL_SEARCH_FALLBACK_DAYS` (по умолчанию 180, из
  конфига), чтобы не фетчить весь ящик. Окно пробрасывается из `bootstrap` → `CliRepl` → `/find`.
- Тулы (`mail.search`, провайдеры) **не меняются** — MCP-путь сохраняется без изменений.
- Вывод `/find` остаётся прежним (список: тема, отправитель, дата, UID). При достижении лимита
  пагинации — предупреждение (как в `/find-all`).

## Capabilities

### New Capabilities

_(нет — команда относится к существующей capability `transport/cli`.)_

### Modified Capabilities

- `transport/cli`: требование «Команда /find» уточняется — поиск выполняется с локальной
  фильтрацией темы/отправителя (на сервер идут только даты), чтобы находить письма, которые
  серверный SEARCH по теме/отправителю пропускает.
