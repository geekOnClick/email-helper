# Design

## Context

Текущий CLI-транспорт (`src/transport/cli/`) содержит guided-команды `/find`, `/find-all`, `/analyze`, `/download`, `/send`, `/add-account`, построенные поверх тулов реестра `mail.*`. Команды `/find`/`/find-all` реализуют локальную фильтрацию темы/отправителя (т.к. серверный IMAP SEARCH Яндекса по ним ненадёжен) через агрегатор `collectAllMessages` в `commands/find-all.ts`. Команды `/download` и `/send` работают без LLM — только поиск/скачивание/отправка. Субагент-анализатор (`src/agents/analyzer.ts`) используется только командой `/analyze` и имеет скил «анализатор писем, не делает рутинных операций».

MCP-путь (оркестратор + helper + тулы `mail.*`) не меняется — там всё работает корректно. Изменения только в CLI-слое.

## Goals / Non-Goals

**Goals:**
- Убрать дублирующие MCP-тулы команды `/find`, `/find-all`, `/download`, `/send`.
- Добавить три «умные» команды, использующие LLM: `/analyze-many`, `/analyze-attachments`, `/smart-send`.
- Переиспользовать проверенный агрегатор `collectAllMessages` и мастер `promptFindAllCriteria` без изменения их логики.
- Сохранить MCP-путь и тулы `mail.*` без изменений.

**Non-Goals:**
- Не меняем тулы `mail.*` (`mail.search`, `mail.fetch`, `mail.downloadAttachments`, `mail.send`) и их спеки.
- Не меняем MCP-путь оркестратора и субагентов (`analyzer.ts`, `helper.ts`, `compose.ts`).
- Не вводим мультимодальный vision (анализ изображений) — вне scope; неподдерживаемые вложения помечаются.
- Не меняем конфигурацию аккаунтов и провайдеров.

## Decisions

### D1: Перенос `collectAllMessages` в shared-утилиту `search-aggregator.ts`

`collectAllMessages` (включая типы `FindAllSearchArgs`, `CollectAllMessagesResult`, `CollectAllMessagesOptions`) переносится из `commands/find-all.ts` в новый `commands/search-aggregator.ts`. Файлы `find.ts` и `find-all.ts` удаляются. Так `/analyze-many` переиспользует проверенную машину批量-поиска (локальная фильтрация темы/отправителя, пагинация) без дублирования. Мастер `promptFindAllCriteria` остаётся в `prompts.ts` (переиспользуется `/analyze-many`).

**Альтернатива:** дублировать логику в `/analyze-many` — отказались (нарушение DRY, риск расхождения с архивной `/find-all`).

### D2: `/analyze-many` — один вызов анализатора со всеми телами

После批量-поиска команда фетчит тела всех найденных писем через `mail.fetch` (последовательно, с потолком `ANALYZE_MANY_MAX_EMAILS`), собирает их в одну инструкцию и вызывает `analyzer.run(instruction)` одним вызовом. Анализатор возвращает структурированный ответ: саммари каждого письма + общий смысл (или указание, что общего смысла нет).

Потолок `ANALYZE_MANY_MAX_EMAILS` (дефолт 10, из env) ограничивает число фетчей и размер контекста LLM. При превышении — анализ первых N + предупреждение об усечении (как в `/find-all` для пагинации).

**Альтернатива:** по одному вызову анализатора на письмо + агрегирующий вызов — отказались (дороже по токенам/латентности, N+1 вызовов).

### D3: `/analyze-attachments` — временная папка + извлечение текста + удаление всегда

Команда скачивает вложения через `mail.downloadAttachments` во **временную папку** (`os.tmpdir()` + уникальный поддиректорий, НЕ системная `~/Загрузки`), извлекает текст утилитой `attachment-text.ts`, передаёт тексты анализатору, выводит саммари и удаляет временную папку в блоке `finally` (всегда — при успехе и при ошибке).

Утилита `extractAttachmentText(path)` (новый `commands/attachment-text.ts`):
- txt/csv/json/html/htm/eml — чтение как UTF-8 (HTML — stripping тегов простым regex);
- pdf — `pdf-parse`;
- docx — `mammoth.extractRawText`;
- xlsx — `xlsx` (чтение листов в текст);
- изображения (png/jpg/gif/webp/bmp) и прочие бинарные — `{ skipped: true, reason: 'неподдерживаемый формат' }`.

**Альтернатива (а):** только UTF-8 без библиотек — отказались (большинство вложений — документы, пользы мало).
**Альтернатива (с):** мультимодальный vision — отказались (требует расширения `ChatMessage` на content-parts и `routerai-client`, выходит за CLI-слой и может затронуть MCP-путь; вне scope).

### D4: `/smart-send` — прямой one-shot LLM-вызов (роль `helper`)

Драфт тела генерируется **прямым вызовом `RouterAiClient`** (`chat()` с ролью `helper`, без тулов и без субагент-цикла) по теме + промпту. Не используется субагент `analyzer` (его скил — «анализатор, не делает рутинных операций», семантически не подходит) и не вводится новый субагент `composer` (минимальное изменение, no new agent registration).

Bootstrap уже создаёт `RouterAiClient` внутренне, но не отдаёт его наружу. Добавляем в `BootstrapResult` поле `llmClient: RouterAiClient` (или фабрику one-shot completion) и пробрасываем в `CliRepl` → `SmartSendCommandDeps`. Команда вызывает `client.chat({ messages, role: 'helper' })`.

Цикл: показ черновика → действие (`отправить`/`отмена`/`править`). При «править» — пользователь вводит промпт-обратную связь одной строкой, модель регенерирует только тело (тема + получатель фиксированы, передаются в каждый вызов как контекст), новый черновик. Без явного потолка итераций (до подтверждения/отмены). Тело — plain text только (соответствует мастеру `/send`).

**Альтернатива (а):** новый субагент `composer` — отказались (лишняя регистрация в `compose.ts`/`bootstrap.ts`, отдельный скил; one-shot проще).
**Альтернатива (с):** оркестратор с тулами — отказался (оверкилл, тулы не нужны для генерации текста).

### D5: Мастер `/smart-send` — три обязательных поля

Новый мастер `promptSmartSendCriteria` (в `prompts.ts`) собирает `тема`, `получатель` (email), `промпт` построчно в формате `ключ - значение` (как остальные guided-команды). Валидация: непустая тема, валидный email, непустой промпт. Пустая строка — завершение: все поля → генерация, иначе отмена. Переиспользует паттерн `parseCriteriaLine`/`isValidEmail` из существующего мастера.

Цикл подтверждения/правки — новый `promptSendAction(io)`: читает одну строку, распознаёт `отправить`/`отмена`/произвольный текст (правка). При правке — `io.readline()` промпта обратной связи.

### D6: Новое env-значение `ANALYZE_MANY_MAX_EMAILS`

Добавляется в `Config` (`src/config/schema.ts`) с дефолтом 10, читается из env через `loader.ts`, пробрасывается через `BootstrapResult` → `CliRepl` → `AnalyzeManyCommandDeps.maxEmails`. По аналогии с существующим `MAIL_SEARCH_FALLBACK_DAYS`.

## Risks / Trade-offs

- **[Большие вложения / много писем → рост токенов LLM]** → Потолок `ANALYZE_MANY_MAX_EMAILS` (дефолт 10) для `/analyze-many`; для `/analyze-attachments` — одно письмо, тела вложений обрезаются при превышении `AGENT_MAX_TOOL_RESULT_CHARS`-подобного лимита (применяем тот же подход, что в анализаторе: усечение + пометка).
- **[Новые зависимости `pdf-parse`/`mammoth`/`xlsx` — безопасность/совместимость]** → Берём стабильные popular-пакеты, изоляция в `attachment-text.ts` (одна точка отказа); при ошибке извлечения — пропуск вложения с пометкой, не роняем команду.
- **[Временные файлы не удалятся при крахе процесса]** → Удаление в `finally` + временная папка в `os.tmpdir()` (ОС чистит при перезагрузке); не кладём в пользовательскую `~/Загрузки`.
- **[LLM-драфт `/smart-send` может проигнорировать промпт обратной связи]** → Передаём в контекст как исходный промпт, так и текущее тело + обратную связь; тема/получатель фиксированы в системном сообщении.
- **[Удаление `/find`/`/find-all`/`/download`/`/send` — BREAKING для пользователей CLI]** → Принято как часть change; MCP-путь (тулы) остаётся, migration описан в delta-спеке.

## Migration Plan

1. Реализовать shared-утилиту `search-aggregator.ts` (перенос `collectAllMessages`) до удаления `find-all.ts`.
2. Реализовать новые команды, обновить `repl.ts`/`prompts.ts`/`format.ts`/`bootstrap.ts`/`index.ts`.
3. Удалить старые команды и их тесты.
4. Добавить зависимости `pdf-parse`/`mammoth`/`xlsx`.
5. Прогнать `tsc`/`lint`/`vitest`.
6. Rollback: git revert change (MCP-путь не затронут, CLI возвращается к старым командам).
