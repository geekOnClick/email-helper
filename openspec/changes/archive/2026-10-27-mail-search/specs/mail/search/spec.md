# Spec Delta

## Purpose

Поиск писем в почтовом ящике по критериям (тема, отправитель, получатель, дата, флаги) с указанием папки и направления (входящие/исходящие), возврат метаданных без тел.

## ADDED Requirements

### Requirement: Поиск по теме

Система SHALL искать письма, тема которых содержит заданную подстроку (без учёта регистра), в указанной папке. Результат SHALL содержать UID, тему, отправителя, дату, флаги.

#### Scenario: Найдены письма по теме

- **WHEN** ищем письма с темой «отчёт» в папке «Входящие»
- **THEN** система возвращает список метаданных писем, в темах которых есть «отчёт»

#### Scenario: Ничего не найдено

- **WHEN** ищем письма с темой, которой нет, в папке
- **THEN** система возвращает пустой список

### Requirement: Поиск по отправителю

Система SHALL искать письма, чей отправитель (From) содержит заданную подстроку.

#### Scenario: Найдены письма от отправителя

- **WHEN** ищем письма от отправителя «ivanov@example.com»
- **THEN** система возвращает метаданные писем, у которых From содержит «ivanov@example.com»

### Requirement: Поиск по дате

Система SHALL искать письма, полученные после (`since`) и/или до (`before`) указанной даты.

#### Scenario: Письма за период

- **WHEN** ищем письма с `since` = 2026-10-01 и `before` = 2026-10-31
- **THEN** система возвращает метаданные писем, полученных в этом периоде

### Requirement: Поиск по папке и направлению

Система SHALL искать в указанной папке. Если задано направление `incoming` — система SHALL искать в папке `\Inbox`; `outgoing` — в `\Sent`. Явно заданная папка имеет приоритет над направлением.

#### Scenario: Поиск во входящих через направление

- **WHEN** ищем письма с направлением `incoming` и без явной папки
- **THEN** система открывает папку «Входящие» (`\Inbox`) и ищет в ней

#### Scenario: Явная папка приоритетнее направления

- **WHEN** ищем с направлением `incoming` и папкой «Archive»
- **THEN** система ищет в «Archive»

### Requirement: Поиск по флагам

Система SHALL поддерживать фильтр по флагам: непрочитанные (`unseen`), помеченные (`flagged`), отвеченные (`answered`).

#### Scenario: Только непрочитанные

- **WHEN** ищем с флагом `unseen=true`
- **THEN** система возвращает только непрочитанные письма

### Requirement: Ограничение и постраничность

Система SHALL поддерживать ограничение количества результатов (`limit`, по умолчанию 50). Результат SHALL содержать общее число найденных и флаг `hasMore`.

#### Scenario: Ограничение результатов

- **WHEN** найдено 100 писем, `limit` = 50
- **THEN** система возвращает 50 элементов, `hasMore` = true

#### Scenario: По умолчанию 50

- **WHEN** критерии без limit
- **THEN** система применяет limit = 50

### Requirement: Требуется активная сессия

Система SHALL отклонять поиск, если для данного логина нет активной IMAP-сессии (созданной тулом `mail.connect`).

#### Scenario: Поиск без подключения

- **WHEN** ищем письма, но сессия для логина не установлена
- **THEN** система возвращает ошибку «подключение не установлено»

### Requirement: Метаданные без тел

Система SHALL возвращать только метаданные писем (UID, тема, отправитель, получатель, дата, флаги, размер), без тел писем. Тело — отдельный тул `mail.fetch`.

#### Scenario: Результат содержит метаданные

- **WHEN** поиск вернул письма
- **THEN** каждое содержит UID, тему, отправителя, дату, флаги и не содержит body

### Requirement: Секреты в ошибках

Система SHALL NOT включать учётные данные или токены в сообщения об ошибках поиска.

#### Scenario: Ошибка поиска без раскрытия секрета

- **WHEN** поиск завершается ошибкой
- **THEN** сообщение об ошибке не содержит пароля и access token
