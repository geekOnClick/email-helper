# Spec Delta

## MODIFIED Requirements

### Requirement: Подключение к ящику по IMAP

Система SHALL устанавливать защищённое IMAP-соединение с сервером провайдера по учётным данным аккаунта и возвращать результат подключения (Яндекс — `imap.yandex.ru:993`, Outlook — `outlook.office365.com:993`). Вызов тулa `mail.connect` SHALL принимать только `login` и `provider`; пароль SHALL извлекаться сервером из реестра аккаунтов (инициализированного из `ACCOUNTS` в `.env`) по паре `(provider, login)`. Система SHALL NOT принимать пароль или иные учётные данные в аргументах вызова тулa.

#### Scenario: Успешное подключение к Яндекс с паролем приложения

- **WHEN** запрашивается подключение к Яндекс-аккаунту с корректным логином и паролем приложения
- **THEN** система устанавливает IMAP-соединение с `imap.yandex.ru:993` (TLS) и возвращает успешный результат

#### Scenario: Успешное подключение к Outlook с выбранной стратегией

- **WHEN** запрашивается подключение к Outlook-аккаунту с корректными учётными данными и работающей стратегией аутентификации
- **THEN** система устанавливает IMAP-соединение с `outlook.office365.com:993` (TLS) и возвращает успешный результат

#### Scenario: Подключение с динамическими кредами, переданными вызывающим агентом

- **WHEN** вызов тулa `mail.connect` содержит блок `credentials` с паролем (динамические креды)
- **THEN** система не принимает пароль по MCP и требует только `provider` + `login`; пароль для авторизации извлекается сервером из `ACCOUNTS` (`.env`), динамическая передача кред исключена

#### Scenario: Динамические креды опущены — fallback на конфигурацию .env

- **WHEN** вызов тулa `mail.connect` содержит `provider` и `login` без блока `credentials`
- **THEN** система ищет аккаунт по паре `(provider, login)` в `ACCOUNTS` (`.env`), извлекает пароль и подключается с ним

#### Scenario: Динамические креды опущены и аккаунт не найден в .env

- **WHEN** вызов тулa `mail.connect` содержит `provider` и `login`, и аккаунт с этой парой отсутствует в `ACCOUNTS`
- **THEN** система возвращает структурированную ошибку `account_not_found` и не пытается подключиться

#### Scenario: Provider не соответствует заведённому аккаунту

- **WHEN** вызов тулa `mail.connect` содержит `login`, для которого в `ACCOUNTS` заведён аккаунт, и `provider`, не совпадающий с заведённым
- **THEN** система возвращает структурированную ошибку `provider_mismatch` и не подключается

#### Scenario: Неверные учётные данные

- **WHEN** учётные данные аккаунта отклонены сервером
- **THEN** система возвращает ошибку аутентификации с понятным сообщением, не раскрывая секрет

#### Scenario: Сервер недоступен

- **WHEN** IMAP-сервер недоступен по сети или превышен таймаут подключения
- **THEN** система возвращает ошибку подключения с указанием провайдера и причины

## ADDED Requirements

### Requirement: Структурированная MCP-ошибка отсутствия аккаунта

При отсутствии заведённого аккаунта для переданных `provider` + `login` (или несовпадении `provider`) тул `mail.connect` SHALL вернуть MCP-результат с признаком `isError: true` и текстовым блоком `content[0].text`, содержащим JSON-объект с полями: `error` (код — `account_not_found` или `provider_mismatch`), `message`, `login`, `provider`, `hint` (подсказка о заведении аккаунта через локальный CLI). Ошибка SHALL NOT содержать паролей.

#### Scenario: Ошибка account_not_found возвращает машиночитаемый JSON

- **WHEN** вызов `mail.connect` передаёт `login` и `provider`, для которых нет заведённого аккаунта
- **THEN** MCP-ответ имеет `isError: true`, а `content[0].text` — валидный JSON с `error: "account_not_found"`, полями `login`, `provider` и `hint`

#### Scenario: Ошибка provider_mismatch возвращает машиночитаемый JSON

- **WHEN** вызов `mail.connect` передаёт `login` с заведённым аккаунтом и несовпадающий `provider`
- **THEN** MCP-ответ имеет `isError: true`, а `content[0].text` — валидный JSON с `error: "provider_mismatch"` и полями `login`, `provider`, `hint`

#### Scenario: Ошибка отсутствия аккаунта не раскрывает пароли

- **WHEN** система возвращает структурированную ошибку отсутствия аккаунта
- **THEN** текст ошибки не содержит пароля ни одного заведённого аккаунта

## REMOVED Requirements

### Requirement: Безопасность динамических учётных данных

**Reason**: Динамическая передача учётных данных (блок `credentials` с `password` через MCP) полностью исключена новым подходом: пароли хранятся только в `.env` сервера и не пересекают MCP-wire. Требование о безопасности динамических кред больше не применимо.

**Migration**: Вместо передачи `credentials` в `mail.connect` заведите аккаунт через локальную CLI-команду `/add-account` (`provider`, `login`, `password`, `authStrategy`), после чего вызывайте `mail.connect` с `provider` + `login`. Пароль будет найден сервером в `ACCOUNTS`.
