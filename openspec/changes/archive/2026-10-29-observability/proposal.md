# Proposal

## Why

Фаза 8 (полировка). Ядро агента (оркестратор, тулы, транспорты CLI + MCP) работает, но observability отсутствует: токены LLM (`Usage`) парсятся и проходят в `ToolLoopResult`/`OrchestratorResult`, но нигде не агрегируются и не выводятся; вызовы тулов исполняются без структурированного лога (есть только UI-прогресс через `onToolEvent`, не пригодный для аудита). Документация проекта неполная — нет `README.md` (точка входа для пользователя/разработчика), `agent.md` устарел (упоминает отменённый Telegram, не отражает MCP). Отсутствуют E2E-сценарии, проверяющие сквозную работу агента через построенные транспорты.

## What Changes

- **NEW** capability `ops/observability`: структурированное логирование вызовов тулов (имя, аргументы-без-секретов, статус ok/error, длительность) и агрегация расходов токенов LLM по сессии агента с отчётом в конце прогона. Секреты (пароли, токены, API-ключи) SHALL NOT попадать в логи.
- **MODIFIED** capability `agent/orchestrator`: оркестратор SHALL агрегировать использование токенов по всем итерациям цикла (сейчас `OrchestratorResult.usage` хранит только последнюю итерацию) и SHALL испускать событие завершения прогона с итоговым отчётом токенов/вызовов для наблюдателя.
- E2E-тесты: сквозные сценарии (поиск→анализ→скачивание→ответ; подключение→поиск→отправка) через CLI и MCP-транспорт со стаб-провайдерами почты/LLM.
- Документация: создать `README.md` (установка, конфигурация, запуск CLI/MCP, тесты, структура); актуализировать `agent.md` (убрать Telegram, добавить MCP, обновить стек/архитектуру).
- Очистка: удалить пустой stub `src/transport/telegram/index.ts` (Фаза 7 отменена).

## Capabilities

### New Capabilities
- `ops/observability`: структурированное логирование вызовов тулов и агрегация/отчёт расходов токенов LLM по сессии агента; запрет попадания секретов в логи.

### Modified Capabilities
- `agent/orchestrator`: агрегация использования токенов по всем итерациям цикла tool-calling (сейчас — только последняя итерация) и событие завершения прогона с итоговым отчётом.

## Impact

- **Код:** `src/agents/loop.ts` (агрегация usage по итерациям), `src/agents/orchestrator.ts` (отчёт токенов/вызовов в `OrchestratorResult`), новый модуль логирования (например `src/observability/logger.ts`), интеграция логгера в `runToolLoop`/`bootstrap`; `src/transport/cli/bootstrap.ts` (вывод отчёта токенов по завершении REPL-сессии); удаление `src/transport/telegram/`.
- **API:** `OrchestratorResult.usage` меняет семантику (агрегат vs последняя итерация) — внутренний тип, но тесты оркестратора проверяют поле; `ToolLoopResult.usage` аналогично. Без изменения внешних MCP/CLI-контрактов.
- **Зависимости:** без новых runtime-зависимостей (логирование — встроенный модуль или тонкая обёртка над `console`/`process.stderr`).
- **Документация:** новый `README.md`, обновлённый `agent.md`.
- **Тесты:** unit-тесты логгера и агрегатора токенов; E2E-тесты для CLI и MCP.
