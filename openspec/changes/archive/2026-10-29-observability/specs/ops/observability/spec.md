# Spec Delta

## ADDED Requirements

### Requirement: Логирование вызовов тулов

Система SHALL логировать каждый исполненный вызов тулa в течение сессии агента: имя тулa, статус завершения (успех/ошибка), длительность исполнения и краткое описание результата или ошибки. Система SHALL NOT записывать сырые секреты (пароли, токены, API-ключи, пароли приложений) в лог вызовов тулов.

#### Scenario: Успешный вызов тулa логируется

- **WHEN** тул исполняется успешно в течение сессии
- **THEN** в лог попадает запись с именем тулa, статусом «успех» и длительностью исполнения

#### Scenario: Ошибка тулa логируется

- **WHEN** тул завершается ошибкой (исключение, невалидные аргументы)
- **THEN** в лог попадает запись с именем тулa, статусом «ошибка» и описанием ошибки

#### Scenario: Длительность вызова фиксируется

- **WHEN** тул исполняется
- **THEN** логируемая запись содержит длительность исполнения тулa в миллисекундах

#### Scenario: Секреты не попадают в лог

- **WHEN** аргументы тулa или его результат содержат учётные данные (пароль, токен, API-ключ)
- **THEN** логируемая запись не содержит сырых секретов; они маскируются или исключаются

### Requirement: Агрегация расходов токенов LLM

Система SHALL агрегировать использование токенов (промпт, генерация, всего) по всем итерациям цикла tool-calling в пределах одного прогона агента и SHALL предоставлять итоговый отчёт по токенам этого прогона. Если провайдер LLM не вернул данные о токенах для итерации, система SHALL учитывать это в отчёте, не прерывая прогон.

#### Scenario: Токены суммируются по итерациям

- **WHEN** прогон агента содержит несколько итераций цикла, каждая из которых вернула использование токенов
- **THEN** итоговый отчёт содержит сумму токенов промпта, генерации и общих по всем итерациям прогона

#### Scenario: Отсутствие данных о токенах

- **WHEN** провайдер LLM не вернул использование токенов для одной или нескольких итераций
- **THEN** система не прерывает прогон и отмечает в отчёте, что данные о токенах неполные или отсутствуют

#### Scenario: Отчёт доступен после прогона

- **WHEN** прогон агента завершён
- **THEN** итоговый отчёт по токенам доступен вызывающей стороне как часть результата прогона

### Requirement: Отчёт по сессии агента

Система SHALL по завершении сессии агента предоставлять сводный отчёт, включающий: число выполненных прогонов (реплик пользователя), суммарное число вызовов тулов с разбивкой на успешные и ошибочные, суммарное использование токенов LLM по всем прогонам. Транспорт SHALL предоставлять этот отчёт пользователю по явному запросу (команда) или при завершении сессии.

#### Scenario: Сводка по завершении сессии

- **WHEN** сессия агента завершается (пользователь выходит из транспорта)
- **THEN** транспорт выводит сводный отчёт с числом прогонов, вызовов тулов и суммарными токенами

#### Scenario: Отчёт по запросу

- **WHEN** пользователь запрашивает отчёт командой транспорта во время сессии
- **THEN** транспорт выводит текущую сводку вызовов тулов и токенов на момент запроса
